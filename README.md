# Микробиология · Аналитика посевов

Программа обработки микробиологических данных (посевы, антибиотикограммы,
эпидемиология по локализациям) с графическим интерфейсом. Формирует готовый
Excel-отчёт из исходного файла лаборатории: базовые листы статистики,
пользовательские листы конструктора и **сравнение клиник**.

## Возможности

- **Новый интерфейс** на [CustomTkinter](https://github.com/TomSchimansky/CustomTkinter):
  тёмная/светлая тема, карточки, скруглённые кнопки, прогресс-бар,
  журнал обработки с цветными метками и строка состояния.
- **Разделение логики и UI**: вся обработка вынесена в `app_core.py`
  (можно использовать без GUI и тестировать автономно).
- **Автоопределение клиник.** Если в исходном файле данные нескольких
  клиник (столбец «Клиника» или первый столбец-разделитель, например
  ВМХ / ВПХ / ГХ), программа определяет их при загрузке файла и предлагает
  выбрать: конкретную клинику, **«Все клиники»** или режим **«Сравнение клиник»**.
- **Режим «Все клиники»**: каждая клиника обрабатывается отдельно, а
  результаты сохраняются в **отдельных файлах** —
  `отчёт — ВМХ.xlsx`, `отчёт — ВПХ.xlsx`, `отчёт — ГХ.xlsx`.
- **Режим «Сравнение клиник»** (отдельный режим работы): проверка
  работоспособности одних и тех же антибиотиков на одни и те же
  микроорганизмы/материал в условиях разных клиник. Базовые листы при этом
  **не создаются** — формируются только два листа:
  1. таблица сравнения (структура как у листа 3: блоки «Антибиотик…»,
     подблоки «Клиника…», строки «микроорганизм × локализация»,
     показатели S/I/R/НД/Total/S%/I%/R%/НД%);
  2. лист с **графиками** сравнения (столбчатые диаграммы S% по клиникам).
- **Конструктор листов**: любые дополнительные листы — группировка по полям
  (клиника, микроорганизм, материал, категория, год/месяц/неделя, пациент…),
  метрики (всего проб, рост, % диагностичных, уникальные пациенты),
  антибиотикограмма по выбранному антибиотику или «Все антибиотики»,
  фильтры (только раны, моча, кровь и катетеры и т. д.), готовые шаблоны,
  сохранение/загрузка пресетов в JSON. В конструкторе тоже доступен режим
  «⚖️ Сравнение клиник» для отдельных листов отчёта.
- **Красивый Excel-отчёт** (включается переключателем):
  - стилизованные шапки таблиц, «зебра» строк, рамки, автоширина;
  - условная подсветка процентов (S% ≥ 80 — зелёный, < 50 — красный);
  - листы **«Сводка»** (ключевые показатели) и **«Данные»**
    (очищенные исходные строки с категорией материала);
  - заморозка заголовков, активным открывается «Сводка».
- **Надёжность**: сообщения передаются через очередь (без вызовов Tk из
  фонового потока), автоматическое имя результата с меткой времени,
  кнопка «Открыть папку результата», отказоустойчивый поиск столбца пациента.

## Структура проекта

| Файл | Назначение |
|---|---|
| `1.py` | Графический интерфейс (запуск: `python 1.py`) |
| `app_core.py` | Ядро: загрузка, определение клиник, статистика, конструктор листов, сравнение клиник, сохранение |
| `sheet_builder.py` | Диалог «Конструктор листов» (карточки листов, режимы, шаблоны, пресеты) |
| `данные.xls` | Пример исходного файла (три клиники: ВМХ, ВПХ, ГХ) |
| `requirements.txt` | Зависимости |

## Установка и запуск

```bash
pip install -r requirements.txt
python 1.py
```

Требования: Python 3.9+, пакеты из `requirements.txt`
(pandas, numpy, openpyxl, customtkinter, xlrd).

Входной файл может быть в формате `.xlsx / .xlsm / .xls`. Жёсткие требования
к оформлению сняты: программа сама находит лист с данными (предпочитая
`TDSheet`, но пробуя и другие), строку заголовков (по словам «Заказ», «Дата»,
«Материал», «Микроорганизм» и их аналогам) и строку с названиями антибиотиков.
Колонки «Дата» и «Материал» необязательны; значения RSI — в правых
столбцах пар (S/I/R/НД). Клиники определяются по столбцу «Клиника» либо по
первому столбцу-разделителю (если в нём повторяются короткие коды, а
остальные колонки заполнены).

## Инструкция по использованию

### Шаг 1. Загрузите исходный файл

1. Нажмите **«Обзор…»** в карточке «Исходный файл» и выберите файл посевов
   (`.xls`, `.xlsx`, `.xlsm`).
2. Программа в фоне прочитает файл и определит:
   - список **клиник** (например: ВМХ, ВПХ, ГХ — с числом посевов у каждой);
   - список **антибиотиков**.
3. Клиники появятся в меню «Клиника:», антибиотики — в панели сравнения
   (если выбран режим сравнения) и в конструкторе листов; ход сканирования
   виден в журнале.

### Шаг 2. Выберите режим обработки (меню «Клиника»)

| Выбор | Что произойдёт |
|---|---|
| Конкретная клиника (напр. **ВМХ**) | Весь отчёт строится только по данным этой клиники |
| **Все клиники** (по умолчанию) | Каждая клиника обрабатывается отдельно; сохраняется **по файлу на клинику** (`… — ВМХ.xlsx`, `… — ВПХ.xlsx`, `… — ГХ.xlsx`) |
| **⚖️ Сравнение клиник** | Отдельный режим: сравнительные листы по отмеченным клиникам, базовые листы не создаются (см. шаг 4) |

Если в файле только одна клиника (или столбца «Клиника» нет), выбор клиники
недоступен — данные обрабатываются как единая выборка.

### Шаг 3. Соберите листы в конструкторе (при необходимости)

1. Нажмите **«🧩 Конструктор листов…»**.
2. Кнопкой **«＋ Добавить лист»** создавайте карточки листов; готовый сценарий
   можно выбрать в выпадающем списке **«Шаблон →»**. Для каждой карточки:
   - **Режим**: «Обычный лист» или «⚖️ Сравнение клиник»;
   - **Группировать по**: любое сочетание полей (микроорганизм, материал,
     категория, год+месяц, пациент…) или «Всё вместе»;
   - **Метрики**: всего проб, с ростом, % положительных, диагностичные,
     уникальные пациенты + антибиотикограмма (выберите антибиотик или
     «Все антибиотики»);
   - **Фильтр**: только с ростом, только раны, только моча и т. д.;
   - **Шаблон**: готовые сценарии (динамика по месяцам, резистентность…).
3. Пресеты: **«💾 Сохранить пресет…» / «📂 Загрузить пресет…»** (JSON) — набор
   листов можно сохранить и применить к другому файлу.
4. Нажмите **«Применить»** — листы из конструктора добавятся к отчёту после
   базовых. Листы 1–3 (базовые) всегда включаются в обычный отчёт
   автоматически.

### Шаг 4. Режим «Сравнение клиник»

1. В меню «Клиника» выберите **«⚖️ Сравнение клиник»**.
2. Под выбором файлов появится панель сравнения:
   - **список антибиотиков** с мультивыбором (Ctrl/Shift), поиском по названию
     и кнопками «Выбрать все» / «Снять всё»; **ничего не отмечено =
     сравниваются все антибиотики**;
   - **чекбоксы клиник** («Клиники для сравнения, отметьте минимум две») —
     заполняются из исходного файла после его выбора;
   - кнопки **«💾 Сохранить настройки сравнения…» /
     «📂 Загрузить настройки сравнения…»** (JSON-пресет: клиники,
     антибиотики, фильтр);
   - строка состояния внизу панели показывает, что именно будет сравниваться.
3. Укажите результирующий файл и нажмите **«▶ Запустить обработку»**.
4. В результате один Excel-файл с двумя листами (имена — по названию сравнения,
   по умолчанию «Сравнение клиник»):
   - таблица сравнения в стиле листа 3: для каждого
     антибиотика идут подблоки по клиникам со **одинаковым порядком строк**
     (микроорганизм × локализация) и показателями S/I/R/НД/Total/S%/I%/R%/НД%,
     плюс строки «ВСЕГО» по клинике;
   - лист **«… (график)»** — столбчатые диаграммы чувствительности
     (S%) по клиникам для наглядного сопоставления.
5. Базовые листы 1–3 в этом режиме **не создаются**.

> Совет: тот же функционал доступен как отдельный лист внутри обычного
> отчёта — в конструкторе листов выберите в карточке режим
> «⚖️ Сравнение клиник», отметьте клиники и антибиотики. Такой лист строится
> по полному файлу независимо от выбранной клиники.

### Шаг 5. Запуск обработки

1. Укажите результирующий файл кнопкой **«Сохранить как…»** (если не указать,
   имя сформировается автоматически с датой/временем).
2. При желании включите/выключите переключатель **«Красивое оформление Excel»**.
3. Нажмите **«▶ Запустить обработку»** — ход работы виден в журнале
   (цветные метки), прогресс — на прогресс-баре.
4. По завершении используйте кнопку **«Открыть папку результата»**.

## Использование без GUI (API ядра)

```python
from app_core import (
    load_data, detect_clinics, get_file_info, run_pipeline,
    run_pipeline_multi_clinic, run_clinic_comparison,
)

# одна клиника / общая выборка
run_pipeline('данные.xls', 'otchet.xlsx', styled=True, log_func=print,
             clinic='ВМХ')

# все клиники -> отдельный файл на каждую
files = run_pipeline_multi_clinic('данные.xls', 'otchet.xlsx',
                                  styled=True, log_func=print)
# {'ВМХ': 'otchet — ВМХ.xlsx', 'ВПХ': ..., 'ГХ': ...}

# сравнение клиник
spec = {'name': 'Сравнение клиник', 'mode': '__compare_clinics__',
        'clinics': ['ВМХ', 'ВПХ'],          # пусто/нет ключа — все клиники
        'antibiotics': [],                  # пусто — все антибиотики
        'compare_by': ['organism', 'material_raw'],
        'filter': 'positive_only'}
run_clinic_comparison('данные.xls', 'compare.xlsx', spec,
                      styled=True, log_func=print)

# что умеет файл
clinics, antibiotics = get_file_info('данные.xls')
```

Функции конструктора: `build_sheet_from_spec(spec, ...)`,
`validate_spec(spec, available_antibiotics)`,
`save_sheet_specs/load_sheet_specs` (пресеты обычных листов),
`save_compare_preset/load_compare_preset` (пресет режима сравнения).

## Частые вопросы

- **Клиники не определились** — проверьте, что есть столбец «Клиника»
  (или первый столбец с короткими повторяющимися кодами). Файл из одного
  раздела будет обработан как единая выборка («Общая выборка»).
- **Режим сравнения выдаёт ошибку про две клиники** — для сравнения нужно
  минимум две разные клиники в файле и минимум две отмеченные.
- **Дублирующиеся заголовки колонок RSI/MIC** — не проблема: ядро обращается
  к колонкам позиционно.
- **Листы с русскими именами обрезаются** — имена листов Excel ограничены
  31 символом, длинные имена сокращаются автоматически.
